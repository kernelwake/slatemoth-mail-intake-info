SlateMoth Mail Intake

Privacy policy

Updated 2026-10-06 for the owner's personal editorial automation.

Purpose and access

The controller receives the owner's self-addressed Muse article candidate mail and checks its three JSON attachments before a separate owner-controlled release pipeline can publish an article. Google authorization uses gmail.readonly. That scope grants read access to the entire connected Gmail mailbox; it is not a provider-enforced permission limited to one subject or folder.

The fixed controller searches Sent messages with the SlateMoth candidate subject, uses bounded reads, and requires the exact owner sender/recipient and expected body/attachments before admitting a candidate. It does not send, modify, label, delete or trash email. A rejected candidate carrier can still be retained as an intake record. Muse's separate mail-composition/sending tool is not this readonly controller and is not granted access by this controller's OAuth authorization.

Data and storage

Candidate message bytes, the three original candidate/review JSON files, hashes, validation decisions, job/attempt records, prepared source and release data, signed permits and executor receipts are stored in the owner's private GitHub controller repository. Source/release files use shared content-addressed storage; immutable Git commits retain historical versions. Temporary GitHub Actions artifacts have a short configured retention period. The candidate has no automatic periodic deletion policy for its durable Git data; removing a current file or branch does not immediately erase Git history or provider backups.

Private data and credentials are not included in the public article. Approved article content and its source citations are published on SlateMoth. A separate public editorial context contains only approved business/editorial facts and published source identity. The controller does not execute mail content. Gmail reader credentials, signing keys and submission credentials remain separate owner-controlled GitHub secrets/jobs; they are not provided to Muse or visitors.

Google user data is used only for the described owner-authorized editorial receipt and release workflow. Mailbox data is not sold or used for advertising. The public informational site has no analytics script, forms, sign-in, or OAuth callback. Its hosting provider, GitHub Pages, logs visitor IP addresses for security purposes under the GitHub privacy statement.

Owner control and removal

The owner can stop the controller by disabling its GitHub enable variable and workflow, revoke this app's Gmail authorization in the Google Account connection settings, and remove the related GitHub Actions secret. Revocation stops future mail access; it does not delete already stored records. To remove retained data, the owner must manage the private repository's working files, reachable Git history, Actions artifacts and any local recovery copies, or delete the private repository as appropriate, subject to GitHub's own retention/backups. There is no claim that a simple file deletion immediately erases all historical copies.

This is an owner-operated personal automation, not a public Gmail service. Questions can be sent to the existing public contact address: slatetor@gmail.com.

This page describes the candidate's data handling. It is not a request to accept new legal terms, a promise of Google production approval, or proof that the unattended production loop is already enabled. The Google OAuth publishing state and long-lived readonly credentials must still be confirmed by the owner.
